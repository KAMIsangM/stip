# 1 简介

## 1.1 目的

本需求规格说明书是对基于多智能体技术的智能互助教学平台的功能需求和性能需求的详细描述。该说明书的预期读者为：

用户；

项目管理人员；

测试人员；

设计人员；

开发人员。

本说明书重点描述了智能互助教学平台MVP阶段（P0优先级）的功能需求，明确所要开发的软件应具有的功能、性能与界面，使系统分析人员及软件开发人员能清楚地了解用户的需求。

## 1.2 范围

本需求规格说明书涵盖智能互助教学平台MVP阶段的全部功能需求，包括：智能课堂生成（F001）、多模态教学内容生成引擎（F002）、课程知识库与知识图谱管理（F003）、语音功能集成（F-Voice）四大核心功能模块。

本说明书不包括P1优先级功能（多智能体协同课堂、自适应学习路径、学情分析与个性化推荐、课后测试与互动知识点课件）和P2优先级功能（双导师智能教学、PPT聚光灯与教学白板、导出与分享、知识图谱驱动的生成控制）的详细需求描述，这些功能将在后续版本的需求文档中另行说明。

# 2 总体概述

## 2.1 软件概述

### 2.1.1 项目介绍

本项目是一个全新的独立项目，旨在构建一个基于多智能体技术的互动教学平台，将传统单向授课转变为沉浸式互动学习体验。平台支持虚拟AI教师实时授课、答疑，并自动生成丰富的多模态互动学习内容。学生可通过自然语言输入学习主题，系统自动生成完整的互动课堂内容。MVP阶段仅面向学生用户，以虚拟AI教师单导师教学为核心模式。

平台的核心价值主张是\"让学习更智能、更互动、更个性\"，致力于搭建一座连接知识与学生的智慧教育桥梁。

### 2.1.2 产品环境介绍

本产品是一个独立的、自我包含的Web应用系统。学生通过浏览器（PC端）访问平台，无需安装额外客户端软件。系统后端部署于云服务器，集成多种第三方AI服务接口（大语言模型、语音合成、语音识别等）。

产品的核心外部依赖包括：

\(1\)
大语言模型服务：DeepSeek、通义千问、Kimi、MiniMax等多提供商，通过统一抽象层实现无缝切换。

\(2\) 语音合成/识别服务：TTS语音合成与ASR语音识别服务提供商。

\(3\) 课程知识库：系统预置的核心课程领域知识图谱数据。

\(2\)
**多模态教学内容生成引擎（F002）：**基于课程大纲和知识图谱，将课程内容自动转化为沉浸式文本、测验、PPT与旁白、音频课程、思维导图、互动式教材六种以上模态形式。

\(4\)
**语音功能集成（F-Voice）：**支持TTS语音合成（AI教师语音授课）和ASR语音识别（学生语音提问），实现语音驱动的互动教学体验。

### 3.2.1 子功能1：主题输入与解析

1 介绍

学生通过文本输入学习主题关键词或自然语言描述，系统解析主题意图，匹配课程领域。

2 输入

  ---------------- ------------------------------------------------------------------------
  **输入项**       **说明**
  学习主题关键词   学生输入的主题文本，如\"数据结构\"\"Python基础\"等，来源为用户键盘输入
  自然语言描述     学生可用自然语言描述学习需求，系统提取核心主题
  ---------------- ------------------------------------------------------------------------

3 处理

系统接收主题输入后，调用大语言模型进行主题分析和意图理解，匹配课程知识库中的领域知识，确定课程范围和知识边界。若主题模糊则提示学生补充描述。

4 输出

  -------------- ----------------------------------------
  **输出项**     **说明**
  主题解析结果   包含主题领域、适用范围、核心知识点列表
  课程大纲草稿   结构化的课程大纲，包含章节、知识点层级
  -------------- ----------------------------------------

### 3.2.2 子功能2：课程大纲生成

1 介绍

基于主题解析结果，系统自动生成结构化课程大纲，包含章节标题、知识点层级、学习目标等信息。

2 输入

  -------------- --------------------------------------------------------
  **输入项**     **说明**
  主题解析结果   来自3.2.1的输出
  知识图谱数据   来自F003的知识点关系数据，用于确保大纲的知识体系完整性
  -------------- --------------------------------------------------------

3 处理

系统基于主题解析结果和知识图谱的前驱后继关系，调用LLM生成符合认知规律的课程大纲。大纲按照由浅入深、知识点逐步展开的逻辑编排，确保知识体系的连贯性和完整性。

4 输出

  ------------ ----------------------------------------------------------
  **输出项**   **说明**
  课程大纲     包含章节标题、知识点层级、学习目标、预计学时的结构化大纲
  ------------ ----------------------------------------------------------

### **3.2.3 子功能3：教学场景编排**

1 介绍

将课程大纲中的每个条目编排为具体的教学场景，确定每个场景使用的教学模态（文本、PPT、音频、测验等）。

2 输入

  -------------- ----------------------------
  **输入项**     **说明**
  课程大纲       来自3.2.2的输出
  场景编排策略   系统预设的教学场景编排规则
  -------------- ----------------------------

3 处理

系统根据知识点的特征（概念型、实践型、综合性等）自动匹配最佳教学模态组合。概念型知识点优先使用沉浸式文本+思维导图，实践型知识点优先使用互动式教材+测验，综合性知识点使用PPT+音频讲解。

4 输出

  -------------- --------------------------------------------
  **输出项**     **说明**
  教学场景列表   每个大纲条目对应的教学场景及其模态组合方案
  -------------- --------------------------------------------

# 4 性能需求

  ------------------------ ------------ ----------------------------

## 4.2 系统开放性需求

系统应支持多种大语言模型提供商的接入，通过统一抽象层实现无缝切换。系统应预留多模态内容类型的扩展接口，支持后续新增内容模态。语音服务应支持多TTS/ASR提供商的可配置切换。

## 4.3 界面友好性需求

系统界面应简洁直观，学生无需培训即可上手使用。交互流程应遵循最小步骤原则，核心学习路径操作步骤不超过3步。界面应提供明确的操作引导和帮助提示。知识图谱可视化应支持缩放、拖拽、搜索等交互操作。

## 4.4 系统可用性需求

MVP阶段系统应支持100人同时在线学习，系统可用性不低于99%（月度统计）。系统应具备基本的故障恢复能力，大语言模型服务不可用时应提供友好提示并支持降级模式。

## 4.5 可管理性需求

系统应提供课程内容的更新和版本管理能力。系统应提供基本的学习数据统计功能（课程完成率、学习时长等）。系统日志应记录关键操作和异常信息，便于问题排查。

# 7 软件质量特性

## 7.1 可靠性

系统应具备以下可靠性要求：

\(1\) 系统可用性不低于99%（月度统计），单次不可用时间不超过4小时。

\(2\)
大语言模型服务调用失败时，系统应自动重试（最多3次），并记录失败日志。

\(3\) 语音服务不可用时，系统应降级为纯文本交互模式，不影响核心学习功能。

\(4\) 用户学习进度数据应实时保存，系统异常重启后数据不丢失。

\(5\) 课程内容生成过程中出现异常时，应提供友好的错误提示和重试选项。

## 7.2 易用性

系统应具备以下易用性要求：

\(1\) 新用户无需培训即可完成核心学习路径操作，学习成本不超过10分钟。

\(2\) 核心操作路径不超过3步：输入主题→生成课程→开始学习。

\(3\) 系统应提供操作引导和上下文帮助，关键功能入口提供悬浮提示。

\(4\) 语音交互应支持中英文混合输入，识别准确率不低于90%。

\(5\) 界面设计应遵循无障碍访问原则，支持键盘导航和屏幕阅读器。

# 9 附录

## **9.1 MVP核心用户旅程**

学生使用平台的MVP核心用户旅程如下：

**步骤1：**学生打开平台，进入首页。

**步骤2：**输入学习主题（如\"数据结构\"）或从预置课程库中选择课程。

**步骤3：**F001智能课堂生成模块自动生成课程大纲。

**步骤4：**F002多模态内容生成引擎基于大纲生成沉浸式文本、PPT、音频、思维导图、测验、互动教材等多模态教学内容。

**步骤5：**F003知识图谱管理模块可视化展示课程知识结构。

**步骤6：**虚拟AI教师以TTS语音方式进行课程讲解。

**步骤7：**学生可通过ASR语音或键盘文字与AI教师互动问答。

**步骤8：**课程学习结束，学习记录自动保存。

## **9.2 MVP功能依赖关系**

MVP四个P0功能之间的核心依赖关系如下：

\(1\) F001（智能课堂生成）→
F002（多模态内容生成）：F001生成的课程大纲是F002的输入。

\(2\) F003（知识图谱管理）→
F001（智能课堂生成）：F003提供的知识图谱数据支撑F001的大纲生成。

\(3\) F003（知识图谱管理）→
F002（多模态内容生成）：F003的知识结构确保F002生成内容与知识体系一致。

\(4\) F002（多模态内容生成）→
F-Voice（语音功能集成）：F002生成的旁白文本和教学文本是F-Voice的输入。
